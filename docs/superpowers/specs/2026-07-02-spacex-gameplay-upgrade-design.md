# AI 创业模拟器：SpaceX 风格与玩法增强设计

## 目标

本次迭代把当前第一版可玩切片升级成更有质感、更有长期反馈的模拟器。方向采用「Mission Control 主局 + Founder Briefing 开局」：主局像发射控制台，黑白冷灰、强对比、高信息密度；开局页保留说明和仪式感，但不做营销落地页。

所有普通文案使用中文。公司名、专有名词和少量关键指标可以保留英文；关键指标必须通过 `title` 或可访问说明给出中文含义。

## UI 与视觉

主视觉采用 SpaceX 式配色：

- 主背景：近黑、深灰。
- 主要文字：白色、冷灰。
- 重点状态：白色边框、红色风险、绿色成功、琥珀色警告。
- 交互控件：硬朗直线、低圆角，圆角不超过 8px。
- 禁止装饰性渐变球、花哨背景、营销页大标题。

主局布局保持工具型密度：

- 顶部：年份季度、公司状态、重置入口。
- 主栏：事件或季度行动、员工季度操作、日志/报告。
- 侧栏：排行榜、融资面板、员工面板、成就入口。
- 移动端：单列排列，不裁切按钮和长文本。

## 初始页

初始页改为 Founder Briefing：

- 增加热血但简洁的玩法说明，解释「公司季度操作 + 员工季度操作 + 事件 + 成就/结局」。
- 背景身份不再只是标签，每个身份有特色说明和属性加成。
- 赛道也提供简短说明和开局倾向。
- 选择背景或赛道时，默认属性和初始指标会产生差异。

背景特色示例：

- 前大模型研究员：技术、模型能力更高；销售和管理更弱。
- 大厂产品经理：产品质量和管理更高；技术不是最强。
- 连续创业者：融资能力和估值叙事更强；创始人股权略低。
- 海外博士：全球化准备更高；国内销售起步较慢。
- 开源维护者：声誉和技术更高；商业化较慢。
- 资源型创始人：现金和人脉更好；声誉风险更高。

实现上允许保留总属性点 24 的平衡，但不同身份/预设必须有明确差异。若初始指标差异进入 `createNewGame`，需要保持旧存档兼容。

## 员工系统

员工姓名改为随机生成，中英文都可出现。生成必须可重复：同一存档、同一招聘顺序下结果稳定，避免刷新后员工改名。

员工季度操作新增到主局：

- 每季度公司操作仍选 2 个。
- 每季度额外选择 1 个员工操作。
- 如果没有员工，员工操作区显示「暂无员工」，并提供招聘提示。

员工操作首版包含：

- 加薪留人：花现金，提高忠诚，降低离职风险。
- 期权刷新：稀释创始人股权，提高忠诚。
- PUA 激励：短期提高士气或产出，但增加疲劳和离职风险。
- 放假修整：降低疲劳，消耗季度产出机会。
- 裁员止血：减少现金消耗或短期延长 runway，但降低士气和声誉。

具体数值必须走 engine helper，UI 不直接改指标。

## 排行榜

新增实时 AI 公司排行榜，显示各大 AI 公司/影射公司状态。它不是联网实时数据，而是游戏内模拟榜：

- DeepDuck、OpenMind、MoralMachine、Green Furnace、CloudSoft、BytePlanet 等已有巨头进入榜单。
- 排名根据游戏年份、市场热度、模型能力、产品质量、全球化和玩家事件动态更新。
- 玩家公司也进入榜单。
- 排名变化要符合现实直觉：大公司基础分高、波动小；玩家公司早期低，突破后跃升；开源冲击和价格战会影响榜单。

实现方式为 deterministic simulated leaderboard：输入 `GameState` 输出榜单，不写入随机状态。

## 成就面板

新增「成就」按钮，打开弹层或侧面板：

- 显示所有成就名称、状态、描述或解锁条件。
- 已解锁成就显示完成状态和描述。
- 未解锁普通成就显示解锁条件。
- 最高等级/隐藏成就显示名称，但条件显示为 `???`。

成就数据需要扩展展示字段，如等级、隐藏条件标记、中文条件描述。不要把条件文案硬编码在 UI 里。

## 中文化与指标解释

普通 UI 文案改为中文，包括按钮、面板标题、说明、事件界面、员工操作。

允许保留关键英文指标：

- ARR
- MRR
- PMF
- Runway
- Gross Margin

这些指标需要 `title` 或可访问说明解释中文含义，例如 `PMF：产品市场匹配度`。

## 随机事件频率

事件触发频率提高，但不能一季度连环刷屏。

规则：

- 每季度最多弹 1 个事件。
- 选择后记入 `resolvedEventIds`，避免同一事件反复出现。
- 提高事件出现概率的方式优先采用增加可触发条件覆盖和选择候选事件，而不是无限重复旧事件。
- 如果多个事件符合条件，按优先级/类别轮换，避免永远只出现表里的第一个事件。

## 可玩性增强

每季度从「2 个公司操作」升级为：

- 2 个公司操作。
- 1 个员工操作（有员工时）。
- 可能触发 1 个随机事件。

这样每季度有经营、组织、外部环境三层反馈。

本轮不做复杂 AI 对手行动树，不做实时联网，不做图形动画大工程。排行榜、事件、员工操作都应先用 deterministic engine 函数实现，保证测试和存档稳定。

## 存档兼容

若 `GameState` 增加字段，需要在 `persistence.ts` 中做 legacy normalization：

- 老存档缺字段时补默认值。
- 无效字段仍然按坏存档清理。

## 测试

需要覆盖：

- 背景/赛道影响初始属性或指标。
- 员工姓名生成稳定。
- 员工季度操作会改变现金、士气、忠诚、疲劳或员工列表。
- 排行榜随玩家指标变化。
- 成就面板能显示普通条件和隐藏 `???`。
- 中文 UI 关键按钮和面板存在。
- 事件在多季度中更容易出现，但不会重复已解决事件。
- 存档迁移能兼容新增字段。

## 非目标

- 不做联网实时排行榜。
- 不上 App Store。
- 不引入后端。
- 不做大型 3D/动画场景。
- 不把 UI 改成营销 landing page。
